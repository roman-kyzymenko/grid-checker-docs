"Grid Checker - Полтава" — це приватний, неурядовий проєкт. Він не пов’язаний з жодним державним органом, постачальником послуг або муніципальною організацією в Україні.

Ця Політика конфіденційності описує, як застосунок обробляє дані на iOS (iPhone та Apple Watch) та Android.

## 1. Загальний огляд

Grid Checker - Полтава:

- **не** збирає персональні дані
- **не** створює облікові записи
- **не** збирає дані про місцезнаходження
- **не** використовує аналітику чи трекінг
- **не** показує рекламу
- **не** обробляє платежі
- використовує лише загальнодоступні дані, що надаються бекендом розробника
- взаємодіє лише з власними API-серверами та сервісами push-повідомлень, описаними в розділі 4

Ваші дані ніколи не продаються, не передаються третім сторонам і не використовуються для відстеження.

## 2. Дані, які ми збираємо

### Ми НЕ збираємо:

- Персональну інформацію (ім’я, email, номер телефону)
- Ідентифікатори пристрою (Device ID, Advertising ID)
- Дані про місцезнаходження
- Контакти, фотографії, медіа чи файли

Токени, які Apple та Google генерують для доставки фонових повідомлень, описано в розділі 4. Розробник їх не збирає.

### Ми ОБРОБЛЯЄМО:

#### 2.1. Технічні дані запитів (стандартні HTTP-логи)

Коли застосунок, віджет або застосунок для Apple Watch надсилає запит до бекенду, сервер отримує технічні метадані, які ваш пристрій передає автоматично:

- IP-адресу
- User agent (модель пристрою, версія ОС)
- Час запиту
- Адресу запиту (наприклад, дату графіка або назву вулиці, яку ви шукали)

Ця інформація використовується лише для безпеки сервера, забезпечення доступності та обмеження навантаження.  
Вона **не** пов’язується з жодним профілем користувача і **не** використовується для відстеження.

#### 2.2. Загальнодоступні дані про відключення

Застосунок відображає:

- графіки відключень електроенергії
- списки вулиць для ручного пошуку

Ці набори даних є публічними та не містять персональної інформації.

## 3. Як працює застосунок

### 3.1. Взаємодія з бекендом

Застосунок використовує власний бекенд розробника для отримання:

- графіків відключень
- списків вулиць для пошуку
- даних для оновлення віджета

Коли ви шукаєте свою чергу за назвою вулиці, введена назва вулиці надсилається на бекенд, щоб знайти відповідні черги. Вона використовується лише для відповіді на цей пошук і не пов’язується з вами.

Інші дані користувачів не передаються.

### 3.2. Поведінка віджета (iOS, watchOS та Android)

Віджети та функції циферблата Apple Watch можуть:

- оновлюватися періодично відповідно до правил ОС
- виконувати фонові вибірки даних
- запитувати оновлену інформацію з бекенду
- відображати актуальні дані про відключення

Усі запити віджета містять лише загальнодоступні дані.  
Віджет **не зберігає** і **не збирає** персональних даних.

### 3.3. Зовнішні посилання

Застосунок може містити посилання на зовнішні сервіси, такі як Telegram-бот розробника.  
Взаємодія з такими сервісами регулюється їхніми власними політиками конфіденційності.

### 3.4. Apple Watch

Застосунок для Apple Watch показує ті самі загальнодоступні графіки, що й застосунок для iPhone. Він отримує їх двома способами:

- самостійно запитує їх із бекенду розробника, як і застосунок для iPhone
- ваш iPhone надсилає йому останній графік і мову застосунку через Apple WatchConnectivity — безпосередньо між вашими пристроями, без серверів розробника

Жодні персональні дані між iPhone та Apple Watch не передаються.

## 4. Push-повідомлення / Тихі фонові повідомлення

Застосунок **не** надсилає користувачам видимих сповіщень.  
Однак версії для iOS (iPhone та Apple Watch) та Android використовують **тихі фонові повідомлення** для оновлення даних віджета або запуску процесу оновлення.

Щоб доставити такі повідомлення, операційна система або сервіс Firebase може згенерувати **непрозорий токен пристрою** (Apple) або **реєстраційний токен** (Google):

- Ці токени необхідні для маршрутизації фонових повідомлень.
- Вони **не** ідентифікують користувача персонально.
- Вони **не** використовуються, **не** зберігаються та **не** обробляються розробником.
- Вони **не** передаються на бекенд розробника.
- Вони можуть бути передані Apple або Google виключно для доставки повідомлення.

Тихі фонові повідомлення:

- **не** містять персональної інформації
- **не** є орієнтованими на конкретний пристрій (використовуються топіки)
- **не** показують банери, значки чи звуки
- використовуються лише для оптимізації часу оновлення віджета

## 4.1. iOS та watchOS (FCM через APNs)

Застосунки для iPhone та Apple Watch використовують Firebase Cloud Messaging (FCM) **лише** для:

- отримання тихих повідомлень за топіками
- оновлення графіків у застосунку, віджетах і функціях циферблата

На пристроях Apple ці повідомлення доставляються через Apple Push Notification Service (APNs).  
Для їх маршрутизації Apple генерує токен пристрою, а Firebase — реєстраційний токен та ідентифікатор інсталяції.  
Ними керують Apple та Google. Розробник **не** отримує до них доступу, не використовує та не зберігає їх.

SDK Firebase Cloud Messaging, який додано до застосунку лише для отримання цих повідомлень, може надсилати Google обмежені технічні діагностичні дані про роботу самого сервісу push-повідомлень (наприклад, чи доставлено повідомлення).  
Це діагностика Google власного сервісу, а не аналітика використання застосунку. Ці дані не пов’язуються з вами і не використовуються для відстеження чи реклами. Розробник бачить лише загальну статистику доставки в консолі Firebase, а не дані окремих користувачів чи пристроїв.

## 4.2. Android (тихі повідомлення FCM)

Версія для Android використовує Firebase Cloud Messaging (FCM) **лише** для:

- отримання тихих повідомлень за топіками
- автоматичного оновлення контенту віджета

Firebase може згенерувати реєстраційний токен та ідентифікатор інсталяції як частину механізму FCM.  
Ними повністю керує Google; розробник їх не використовує і не зберігає.

Як і на iOS, SDK Firebase Cloud Messaging може надсилати Google обмежені технічні діагностичні дані про роботу самого сервісу push-повідомлень (наприклад, чи доставлено повідомлення).  
Це діагностика Google власного сервісу, а не аналітика використання застосунку. Ці дані не пов’язуються з вами і не використовуються для відстеження чи реклами. Розробник бачить лише загальну статистику доставки в консолі Firebase, а не дані окремих користувачів чи пристроїв.

Жодних видимих сповіщень на жодній платформі не відображається.

## 5. Платформно-специфічна інформація

### 5.1. iOS та watchOS

Застосунки для iPhone та Apple Watch можуть використовувати такі функції системи:

- **WidgetKit** — відображає графіки у віджетах на головному екрані, екрані блокування, у Динамічному стосі та у функціях циферблата
- **Фонове оновлювання** — для періодичних оновлень на iPhone та Apple Watch
- **Firebase Cloud Messaging (через APNs)** — тихі повідомлення для запуску оновлень
- **App Groups** — для зберігання налаштувань і кешу графіків, спільних для застосунку та його віджетів (без персональних даних)
- **WatchConnectivity** — передає останній графік і мову застосунку з iPhone на Apple Watch

Жодні персональні дані в App Groups не зберігаються.

### 5.2. Android

Версія для Android може використовувати:

- **App Widgets Framework** — для відображення графіків
- **Фонові оновлення**, що контролюються ОС Android
- **Firebase Cloud Messaging (FCM)** — для тихих фонових оновлень
- **SharedPreferences** — для зберігання налаштувань віджета (без персональних даних)

Жодні персональні або унікальні ідентифікувальні дані не зберігаються.
